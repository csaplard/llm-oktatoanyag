01 · Fejezet

Változó és típus

A változó egy megcímkézett doboz. A címkét te adod, a tartalmat te teszed bele. Semmi több misztikum nincs benne.

# karima adatai
nevleges_atmero = 150          # int — egész szám
nyomasfokozat = 40             # int
tomeg_kg = 18.4                # float — tizedes
anyagminoseg = "P250GH"       # str — szöveg
hegesztheto = True            # bool — igaz/hamis

print(anyagminoseg, nevleges_atmero)

Négy típus, amivel a munkaidőd 90%-át tölteni fogod: int, float, str, bool. A típus nem dekoráció — meghatározza, mit lehet csinálni az értékkel.

3 + 4            # 7 — összeadás
"3" + "4"        # "34" — összefűzés!
"3" + 4          # TypeError — hiba
Klasszikus buktató Ha CSV-ből vagy beviteli mezőből olvasol számot, az szöveg-ként érkezik. A "150" nem ugyanaz, mint a 150. Átalakítás: int("150") vagy float("18.4").

f-string: szöveg és érték együtt

jel = f"DN{nevleges_atmero} PN{nyomasfokozat} — {anyagminoseg}"
print(jel)   # DN150 PN40 — P250GH
Mélyebben — miért nincs típusdeklaráció?

Pythonban a típus az értékhez tartozik, nem a változóhoz. Ugyanaz a név ma int-et, holnap str-t tarthat. Ez kényelmes, de ez a leggyakoribb forrása a későn kiderülő hibáknak. Ezért írnak sokan type hint-et: tomeg_kg: float = 18.4 — a Python nem kényszeríti ki, de a szerkesztő szól, és az olvasó érti.

Lista

A lista sorrendtartó gyűjtemény. Akkor használod, ha ugyanolyan fajta dolgokból van több: mérési értékek, karimaméretek, hegesztési varratok azonosítói.

meresek = [4.12, 4.09, 4.15, 3.98, 4.20]

print(meresek[0])       # 4.12 — az első elem indexe 0!
print(meresek[-1])      # 4.20 — az utolsó
print(len(meresek))     # 5 — hány elem van

meresek.append(4.07)   # hozzáfűz a végére
meresek.remove(3.98)   # kivesz egy konkrét értéket
Nulláról indexelünk Az első elem a [0]. Egy ötelemű lista utolsó eleme a [4]. Az [5] már IndexError. Ez az első hét leggyakoribb hibája, és soha nem szűnik meg teljesen.

Szeletelés

meresek[1:3]     # [4.09, 4.15] — 1-től 3-ig, a 3 NEM kell

meresek[-2:]     # utolsó kettő

Dict — kulcs és érték

Ha a listában ugyanolyan fajta dolgokból van sok, a dictben egy dolog különböző tulajdonságai vannak. Egy karima nem öt szám egymás után, hanem átmérő, nyomásfokozat, anyag, tömeg — mindegyik névvel.

karima = {
    "dn": 150,
    "pn": 40,
    "anyag": "P250GH",
    "tomeg_kg": 18.4,
}

print(karima["anyag"])            # P250GH
print(karima.get("szabvany"))     # None — nincs ilyen kulcs, de nem hal meg
print(karima.get("szabvany", "EN 1092-1"))  # alapérték

karima["gyarto"] = "Kovács Kft"   # új kulcs felvétele
Mikor melyik lista[0] hibát dob, ha nincs elem. dict["kulcs"] szintén (KeyError). A .get() viszont csendben None-t ad. Éles kódban a .get() alapértékkel gyakran biztonságosabb — de vigyázz: a csendes None később messzebb robban.

Lista dictekből — ez a leggyakoribb szerkezet

keszlet = [
    {"dn": 50,  "pn": 16, "db": 12},
    {"dn": 80,  "pn": 16, "db": 4},
    {"dn": 150, "pn": 40, "db": 0},
]

print(keszlet[1]["dn"])   # 80

Ez a forma fog visszaköszönni minden CSV-beolvasásnál, minden API-válasznál és minden adatbázis-lekérdezésnél. Ha ezt érted, a későbbi anyag fele már ismerős lesz.

Feltétel

Az if ott dönt, ahol te is döntenél. A gépészeti példák pont ilyenek: elfogadható-e a mérés, kell-e csere, melyik szabvány szerint kell eljárni.

meret = 4.15
nevleges = 4.00
turees = 0.10

if abs(meret - nevleges) <= turees:
    print("MEGFELELT")
elif meret > nevleges:
    print("FELSŐ HATÁR FELETT")
else:
    print("ALSÓ HATÁR ALATT")
A behúzás nem stílus Pythonban a behúzás (4 szóköz) a szintaxis része. Ami beljebb van, az tartozik az if-hez. Rossz behúzás = más program, vagy IndentationError. Ez a nyelv egyetlen igazán szokatlan vonása; egy hét alatt megszokod.

Ciklus

Ha egy műveletet sok elemen kell elvégezned, nem másolod ötvenszer. A for végigmegy egy gyűjteményen.

meresek = [4.12, 4.09, 4.15, 3.98]

for ertek in meresek:
    print(ertek)

Az ertek nevet te adod, és minden körben a következő elemet tartalmazza. Ennyi.

Ciklus + feltétel = szűrés

hibas = []

for ertek in meresek:
    if abs(ertek - 4.00) > 0.10:
        hibas.append(ertek)

print(f"{len(hibas)} db kiesett a tűrésből")

Dictek listáján végigmenni

for tetel in keszlet:
    if tetel["db"] == 0:
        print(f"ELFOGYOTT: DN{tetel['dn']} PN{tetel['pn']}")
Számláló, ha kell Ha a sorszám is érdekel: for i, ertek in enumerate(meresek): — az i a 0-tól induló index.
Mélyebben — list comprehension

A fenti szűrés egy sorban is leírható:

hibas = [e for e in meresek if abs(e - 4.00) > 0.10]

Tömör és pythonos, de az első hónapban maradj a hosszú formánál. Előbb tudj gondolkodni ciklusban, csak utána rövidíts. A rövid forma nem okosabb kód, csak kevesebb sor.

Függvény

A függvény egy megnevezett művelet, amit többször használsz. Ha ugyanazt a kódot kétszer másolod, függvény kell.

def megfelelt(meret, nevleges, turees):
    """Igaz, ha a mért érték a tűrésmezőn belül van."""
    return abs(meret - nevleges) <= turees


if megfelelt(4.05, 4.00, 0.10):
    print("OK")

Három rész: a név (megfelelt), a bemenetek (meret, nevleges, turees) és a visszatérési érték (return). Ha nincs return, a függvény None-t ad vissza — ez is gyakori hibaforrás.

Alapértelmezett paraméter

def megfelelt(meret, nevleges, turees=0.10):
    return abs(meret - nevleges) <= turees

megfelelt(4.05, 4.00)              # 0.10-zel számol
megfelelt(4.05, 4.00, turees=0.02)  # felülírva
Jó függvény ismérve Egy dolgot csinál, és a neve elárulja, mit. Ha a névbe „és" kerül (beolvas_es_kiertekel), akkor két függvény kell. Ez a szabály többet ér, mint bármilyen szintaktikai tudás — és interjún erről kérdeznek.
Buktató A print() és a return nem ugyanaz. A print kiír a képernyőre, a return értéket ad vissza a hívónak. Számoló függvényben szinte mindig return kell.

Hibakezelés

A kód el fog hasalni. A kérdés csak az, hogy kontrolláltan vagy váratlanul. Ez a te területeden nem elméleti különbség.

try:
    pn = int(sor["pn"])
except ValueError:
    print(f"Hibás nyomásérték: {sor['pn']}")
    pn = None
except KeyError:
    print("Hiányzik a pn oszlop")
    pn = None

A leggyakoribb hibatípusok

HibaMit jelent
ValueErrorJó típus, rossz érték — int("kismedve")
TypeErrorRossz típus — "3" + 4
KeyErrorNincs ilyen kulcs a dictben
IndexErrorNincs ilyen indexű elem a listában
FileNotFoundErrorNincs meg a fájl
ZeroDivisionErrorNullával osztás
Amit soha Ne írj except: vagy except Exception: pass formát. Ez elnyeli az összes hibát, beleértve azokat is, amikről tudnod kellene. Egy elnyelt hiba rosszabb, mint egy leálló program — a leálló programról tudsz, az elnyeltről nem.
Mélyebben — mikor kapd el, és mikor ne

Csak azt a hibát kapd el, amire van értelmes válaszod. Ha a válaszod annyi, hogy „kiírom és megyek tovább", akkor általában jobb hagyni felszállni, és a hívó szinten dönteni. A hibakezelés nem a hiba eltüntetéséről szól, hanem arról, hogy a rendszer ismert állapotba kerüljön.

Éles rendszernél a print helyett logging a helyes megoldás — időbélyeggel, szinttel, fájlba. A 3. hónapban jön.

08 · Fejezet

Fájl, CSV, JSON

Itt kezd a Python valódi eszközzé válni: amikor nem beírt adatokkal, hanem a saját fájljaiddal dolgozol.

Szövegfájl

with open("naplo.txt", encoding="utf-8") as f:
    for sor in f:
        print(sor.strip())

A with gondoskodik róla, hogy a fájl bezáruljon akkor is, ha hiba történik. A strip() levágja a sorvégi újsort. Az encoding="utf-8" nélkül az ékezetek elszállnak — magyar adatokkal ez nem opcionális.

CSV — a munkahelyi adat 90%-a

import csv

with open("karimak.csv", encoding="utf-8", newline="") as f:
    olvaso = csv.DictReader(f)
    for sor in olvaso:
        print(sor["dn"], sor["anyag"])

A DictReader minden sort dictté alakít, a fejléc alapján. Vagyis pontosan azt a szerkezetet kapod, amit a 3. fejezetben építettél kézzel.

Excelből jövő CSV A magyar Excel gyakran pontosvesszővel ment, nem vesszővel, és a tizedesjel vessző. Ilyenkor: csv.DictReader(f, delimiter=";"), a számoknál pedig float(ertek.replace(",", ".")). Ez nem kivétel, hanem az alapeset a te környezetedben.

JSON — a gépek nyelve

import json

# kiírás
with open("keszlet.json", "w", encoding="utf-8") as f:
    json.dump(keszlet, f, ensure_ascii=False, indent=2)

# beolvasás
with open("keszlet.json", encoding="utf-8") as f:
    keszlet = json.load(f)

A JSON szerkezete pontosan a Python listák és dictek szerkezete. Ezért lesz ismerős minden API-válasz — a 4. hónapban ez fizet vissza.

Osztály — alapszinten

Az osztály összecsomagolja az adatot és a rá vonatkozó műveleteket. Nem kell szeretni, és nem kell mindent osztályba tenni — de olvasni tudnod kell, mert minden könyvtár így épül.

class Karima:
    def __init__(self, dn, pn, anyag):
        self.dn = dn
        self.pn = pn
        self.anyag = anyag

    def jelolés(self):
        return f"DN{self.dn} PN{self.pn} {self.anyag}"


k = Karima(150, 40, "P250GH")
print(k.jelolés())     # DN150 PN40 P250GH
print(k.dn)            # 150

Az __init__ a létrehozáskor fut le. A self maga a példány — minden metódus első paramétere, és nem te adod meg hívásnál.

Mikor kell osztály Ha ugyanaz az adathalmaz és a rá vonatkozó műveletek együtt mozognak, és több példány van belőlük. Egyszerű adattároláshoz a dict vagy a dataclass elég. A „mindent osztályba" reflex java-örökség, Pythonban nem érdem.
Mélyebben — dataclass 
from dataclasses import dataclass

@dataclass
class Karima:
    dn: int
    pn: int
    anyag: str

Ugyanaz, kevesebb gépeléssel: automatikus __init__, olvasható kiírás, összehasonlíthatóság. Adatot tároló osztályoknál szinte mindig ez a jobb választás.

venv és pip

Minden projektnek saját, elkülönített környezete van. Így nem törik el az egyik projekt attól, hogy a másikhoz frissítettél egy csomagot.

# környezet létrehozása (a projekt mappájában)
python -m venv .venv

# aktiválás — Windows
.venv\Scripts\activate

# aktiválás — Linux/Mac
source .venv/bin/activate

# csomag telepítése
pip install requests

# a jelenlegi állapot rögzítése
pip freeze > requirements.txt

# máshol ugyanaz visszaállítható
pip install -r requirements.txt
Miért számít A requirements.txt az, ami miatt a kódod más gépen is fut. Ez nem formalitás: „nálam működik" a szoftvermérnökség legrégebbi kifogása, és a venv az egyik válasz rá.
Ne kövesd verziókövetésben A .venv mappát soha ne tedd gitbe — nagy, gépfüggő, és felesleges. Erre való a .gitignore.

Git

Nem AI, nem is Python — de enélkül a portfóliód nem létezik. A git az, ami megmutatja, hogy dolgozol: mikor, mit, milyen lépésekben.

git init                      # új repo a mappában
git status                    # mi változott
git add .                     # változások előkészítése
git commit -m "CSV beolvasás"  # mentés üzenettel
git log --oneline             # előzmények

Ágak

git branch turesvizsgalat     # új ág
git switch turesvizsgalat     # átváltás

Commit-üzenet Azt írd le, mit és miért, ne azt, hogy „módosítás" vagy „javítás2". Jó: tűrésellenőrzés kiterjesztése alsó határra. Egy interjúztató végignézi a commit-listádat — az árulkodóbb, mint a kód maga.
.gitignore Legalább ennyi legyen benne: .venv/, __pycache__/, *.pyc, és minden, ami céges adatot vagy kulcsot tartalmaz. Egy véletlenül feltöltött API-kulcs vagy üzemi adat visszavonhatatlan.

13 · Zárófeladat

Karimanapló-elemző

Nyolc hét után ezt kell tudnod megírni — segítség nélkül, két-három óra alatt. Ha megy, készen állsz a 3. hónapra.

A feladat

Készíts eszközt, ami beolvas egy CSV-t mérési adatokkal, és jelentést ad arról, mi esett ki a tűrésből.

Bemenet

azonosito;dn;pn;anyag;mert_vastagsag;nevleges_vastagsag
K-001;150;40;P250GH;4,12;4,00
K-002;80;16;P250GH;3,74;4,00
K-003;150;40;16Mo3;4,08;4,00

Követelmények

  1. Olvassa be a CSV-t (pontosvessző, tizedesvessző, UTF-8)
  2. Számolja ki soronként az eltérést a névlegestől
  3. Jelölje meg, ami ±0,10 mm-en kívül esik
  4. Írja ki: összes tétel, megfelelt, nem felelt meg, átlagos eltérés
  5. Mentse a hibás tételeket külön CSV-be
  6. Kezelje: hiányzó fájl, hiányzó oszlop, számmá nem alakítható érték
  7. Legyen legalább három függvény, külön modulokban
